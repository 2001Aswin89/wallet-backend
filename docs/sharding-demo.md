# Consistent hashing demo

100,000 user ids routed over 4 shards, then a 5th shard added. Generated by `python -m scripts.hash_ring_demo`.

- **1 virtual node(s) per shard:** busiest/least-busy shard is within 12.9% of the ideal 25,000 keys (21,775, 27,455, 27,372, 23,398).
- **10 virtual node(s) per shard:** busiest/least-busy shard is within 42.2% of the ideal 25,000 keys (14,451, 29,150, 29,136, 27,263).
- **100 virtual node(s) per shard:** busiest/least-busy shard is within 11.9% of the ideal 25,000 keys (26,275, 22,389, 27,968, 23,368).
- **400 virtual node(s) per shard:** busiest/least-busy shard is within 6.7% of the ideal 25,000 keys (26,006, 23,443, 23,885, 26,666).

## Distribution with 100 virtual nodes per shard

| shard-4 | 23,368 | 23.4% |

## Adding a 5th shard

| routing | keys that change shard | share of all keys |
|---|---|---|
| consistent hash ring (100 vnodes) | 20,149 | 20.1% |
| `user_id % N` (N from 4 to 5) | 80,000 | 80.0% |

Ideal for 4 to 5 shards is 1/5 = 20.0%. Every key that moved on the ring moved to the new shard (none shuffled between old shards): **True**.
